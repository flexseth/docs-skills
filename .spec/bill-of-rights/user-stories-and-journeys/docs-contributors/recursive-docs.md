# Recursive Documentation Contributor

Whether new or a seasoned docs contributor, the recursive issue search can be challenging. 

This user journey represents a contributor who has had to go through many pages of docs, multiple checklists, conversations and progress reports scattered among various surfaces to try to determine the current state of a docs update.

# Questions
- [ ] What is the current state of the docs update?
- [ ] What's missing (it took me 5 minutes to look over the pages, notice she did not update screenshots?)
- [ ] What changes need to be made? Did the docs update contributor **correctly** address these?

# Challenges
- For a first time contributor they have to review multiple pages on GitHub for a single issue
- Checklists are not consolidated to a single page, they must review a closed issue to view the issue template
- Conversations happen in multiple contexts about a single issue
- No movement on the issue, even though someone has provided feedback 4 months ago
