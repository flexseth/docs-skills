# Documentation Team Style Guide

The WordPress Documentation Team maintains a style guide for writing technical content.

The WordPress [Documentation Style Guide](https://make.wordpress.org/docs/style-guide/) sets the rules and standards for drafting developer and end-user documentation across the WordPress ecosystem. Its goal is to keep information clear, accurate, and consistent for a global audience with a wide range of technical skill.

See and memorize the [Handbooks & HelpHub style and formatting guide](https://make.wordpress.org/docs/handbook/documentation-team-handbook/handbooks-style-and-formatting-guide/) for an overview of the conventions used in WordPress documentation.


## Key Style and Formatting Standards

- **Tone and voice:** Write in an informally knowledgeable, concise tone, addressing the reader as "you." Keep each article focused on one topic, and each paragraph on one major point.
- **Document structure:** Use sequential heading levels (`<h2>` through `<h6>`). Avoid large blocks of text.
- **UI components and paths:** When guiding users through navigation or dashboard options, show clear `Menu > Item` paths and name Blocks explicitly.
- **Alert shortcodes:** Highlight important context with alert boxes: `info`, `tip`, `alert`, `warning`, or `tutorial`.
- **[Code in text:](https://developer.wordpress.org/reference/)** Wrap code elements in shortcodes or `<code>` tags. Link them to the official WordPress Code Reference where possible.

## Accessibility and Inclusivity

- **Global audience:** Use unambiguous language, avoid excessive claims, and limit abbreviations and jargon. If jargon is unavoidable, expand it on first use.
- **Visual assets:** Full-size images and carefully resized browser screenshots are encouraged, but do not rely on them alone. Videos and animated GIFs need play and pause controls.
- **Link text:** Use descriptive, unique anchor text. Avoid vague phrases such as "click here" or "read more."
- **Coding standards alignment:** Documentation follows standard web principles and accessibility targets. It aligns with the WordPress Coding Standards Handbook, which commits to WCAG Level AA compliance for modern elements.
