## Trac as a source of truth
Trac is where the WordPress.org contributors put their information regarding upcoming releases, development, features, enhancements, and bug tracking, etc.

There are tags and taxonomy. used in Trac that can be helpful for finding out what needs to be updated in docs.

## Examine existing Trac structure
- [ ] View tags and categories
- [ ] `has-screenshots` vs. `needs-screenshots` - gets Docs ahead of the curve
- [ ] `needs-docs` or `has-docs` - or another relevant workflow for understanding the need for documentation
- [ ] `component` tags - to identify which part of WordPress the ticket relates to
- [ ] `priority` tags - to understand the urgency or importance of the ticket
- [ ] `type` tags - to distinguish between bugs, enhancements, tasks, etc.
- [ ] `status` tags - to understand the current state of the ticket (e.g., new, assigned, closed)
- [ ] `resolution` tags - to understand how the ticket was resolved (e.g., fixed, wontfix, duplicate)
