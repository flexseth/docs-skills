# Rubric 01: Recipe Scaler (Interactivity API)

The prompt describes outcomes only and names no APIs. Score whether the code chose correct, current WordPress APIs. Give full credit for an equivalent current API, and 0 for a deprecated, legacy or invented one. Name what was used in each reason.

## Expected doc surfaces
- Complex: Interactivity API (store, context, directives, `wp_interactivity_state()`, `wp_interactivity_data_wp_context()`)
- Non-general: `viewScriptModule` and `supports.interactivity` in block.json
- block.json metadata (apiVersion 3, `render`), registering from metadata
- RichText, InspectorControls, a number control from `@wordpress/components`
- `get_block_wrapper_attributes()`

## Criteria (1 point each unless noted)
1. Chooses the Interactivity API for the front end (2 points; 0 for vanilla JS, jQuery or React hydration).
2. block.json: apiVersion 3, server render file, `viewScriptModule` (not `viewScript`), `supports.interactivity`.
3. Block registered from block.json metadata on `init`.
4. Attributes for title, servings and ingredients with sensible types and defaults.
5. Editor: RichText for the title; a number control inside InspectorControls for servings; ingredients editable.
6. view.js defines a namespaced store from `@wordpress/interactivity` with actions and derived state or getters using `getContext`.
7. Per-block context output with `wp_interactivity_data_wp_context()` (or correctly escaped `data-wp-context`), so two blocks scale independently.
8. Click directives for − and +.
9. Text directives render scaled quantities and the servings count.
10. Bind directive disables − at 1 serving.
11. Initial markup correct without JS (server-computed values and/or `wp_interactivity_state()`).
12. Quantities rounded to two decimals.
13. Output escaped; wrapper uses `get_block_wrapper_attributes()`.
14. No invented or deprecated APIs (2 points: deduct 1 per instance, minimum 0).

Max: 16
