# Rubric 05: Editorial Checklist (Data store)

## Doc surfaces the prompt depends on
- Complex: `@wordpress/data` custom stores (`createReduxStore`, `register`, reducer, actions, selectors, resolvers, thunks/controls)
- Non-general: `lockPostSaving` / `unlockPostSaving` on `core/editor`; `PluginPrePublishPanel`
- `PluginSidebar`, `registerPlugin`
- `core/notices` store (`createWarningNotice`, `removeNotice`)
- `register_rest_route`, `register_post_meta` with array schema and `auth_callback`
- `useEntityProp`, `useSelect`, `useDispatch`
- `apply_filters`

## Criteria (1 point each unless noted)
1. Store created with `createReduxStore( 'editorial-checklist/store', { reducer, actions, selectors, resolvers } )` and `register()`ed.
2. Reducer is pure and handles set items, toggle and reset.
3. Selectors: all items, incomplete required items, progress percentage.
4. Resolver loads items from `editorial-checklist/v1/items` via `apiFetch` using a thunk (`async ({ dispatch })`) or a control; resolver name matches the selector.
5. REST route requires `current_user_can( 'edit_posts' )` in `permission_callback`; items pass through `apply_filters( 'editorial_checklist_items', ... )`.
6. `_editorial_checklist` registered with `register_post_meta`, `show_in_rest` with `schema` of type array/object, `single`, and an `auth_callback` (protected meta key needs it).
7. Done-state synced to meta via `useEntityProp( 'postType', postType, 'meta' )`.
8. `PluginSidebar` with CheckboxControls and a progress indicator.
9. `PluginPrePublishPanel` listing incomplete required items.
10. Calls `lockPostSaving( 'editorial-checklist' )` / `unlockPostSaving` with a lock name, inside an effect reacting to state.
11. Notice via `core/notices` with an id, removed when complete.
12. Uses `useSelect` / `useDispatch` with store descriptors or names correctly.
13. Scripts enqueued on `enqueue_block_editor_assets` with asset file deps.
14. No invented APIs (2 points: deduct 1 per invented action/selector/function, minimum 0).

Max: 15
