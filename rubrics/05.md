# Rubric 05: Editorial Checklist (Data store)

The prompt describes outcomes only and names no APIs. Score whether the code chose correct, current WordPress APIs. Give full credit for an equivalent current API, and 0 for a deprecated, legacy or invented one. Name what was used in each reason.

## Expected doc surfaces
- Complex: `@wordpress/data` custom stores (`createReduxStore`, `register`, reducer, actions, selectors, resolvers or thunks)
- Non-general: `lockPostSaving` / `unlockPostSaving` on `core/editor`; `PluginPrePublishPanel`
- `PluginSidebar`, `registerPlugin`; `core/notices`
- `register_rest_route`, `register_post_meta` (array schema, `auth_callback`), `apply_filters`
- `useEntityProp`, `useSelect`, `useDispatch`

## Criteria (1 point each unless noted)
1. Progress is readable from other plugins' JS via a registered data store (`createReduxStore` + `register`) (2 points; 0 for component state, a global variable or a custom event only).
2. Reducer handles setting items and toggling.
3. Selectors for items, incomplete required items, and progress.
4. Items loaded from the server through a resolver or thunk using `apiFetch`.
5. Server endpoint requires `edit_posts` in its permission_callback.
6. Items pass through a PHP filter (`apply_filters`) so other plugins can change them.
7. Checked state saved in post meta registered with `register_post_meta` (`show_in_rest` with an array/object schema; `auth_callback` if protected).
8. State synced with meta via `useEntityProp` (or core-data equivalent).
9. `PluginSidebar` with checkboxes and a progress indicator.
10. `PluginPrePublishPanel` lists unfinished required items.
11. Publishing blocked with `lockPostSaving` / `unlockPostSaving` and a lock name (not by disabling buttons in the DOM).
12. Notice through the `core/notices` store with an id, removed when complete.
13. Scripts enqueued on `enqueue_block_editor_assets` with the asset file.
14. No invented or deprecated APIs (2 points: deduct 1 per instance, minimum 0).

Max: 16
