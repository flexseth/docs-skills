# Rubric 06: Block Visibility Rules (JS Hooks)

## Doc surfaces the prompt depends on
- Complex: `@wordpress/hooks` (`addFilter`, `applyFilters`, `doAction`, namespaces) and block filters reference
- Non-general: `editor.BlockListBlock` filter; `register_block_type_args` for all blocks; `current_datetime()` / `wp_date()`
- `blocks.registerBlockType`, `editor.BlockEdit`, `createHigherOrderComponent`
- `hasBlockSupport`
- RadioControl, DateTimePicker, InspectorControls
- `render_block` filter
- `enqueue_block_editor_assets`, `index.asset.php`

## Criteria (1 point each unless noted)
1. `addFilter( 'blocks.registerBlockType', 'namespace/...', fn )` adds `visibilityRule` (type object, with default) skipping `core/freeform` and blocks without `customClassName` support (`hasBlockSupport`).
2. `editor.BlockEdit` HOC via `createHigherOrderComponent` renders InspectorControls panel and passes through `BlockEdit` props.
3. RadioControl for type; DateTimePicker(s) shown only for `date-range`.
4. `editor.BlockListBlock` HOC adds `has-visibility-rule` via `className` / `wrapperProps`.
5. Editor stylesheet provided and enqueued for the dashed outline.
6. `doAction( 'blockVisibilityRules.ruleChanged', ... )` fires on change.
7. `applyFilters( 'blockVisibilityRules.ruleTypes', defaults )` builds the radio options.
8. PHP `register_block_type_args` adds the attribute schema for all blocks.
9. `render_block` filter returns `''` when the rule fails, otherwise the content unchanged.
10. Logged-in check via `is_user_logged_in()`; dates compared in site timezone (`current_datetime()`, `wp_date()`, or `DateTimeImmutable` with `wp_timezone()`).
11. `apply_filters( 'block_visibility_rules_match', $match, $block, ... )` lets the result be overridden.
12. Editor assets enqueued from `build/index.asset.php` (dependencies + version).
13. No invented APIs (2 points: deduct 1 per invented hook name/function, minimum 0).

Max: 14
