# Rubric 02: Team Directory (REST API)

The prompt describes outcomes only and names no APIs. Score whether the code chose correct, current WordPress APIs. Give full credit for an equivalent current API, and 0 for a deprecated, legacy or invented one. Name what was used in each reason.

## Expected doc surfaces
- Complex: REST API handbook (custom routes, args, permission_callback, schema, pagination headers)
- Non-general: `PluginDocumentSettingPanel`, `useEntityProp`
- `register_post_type` (`show_in_rest`, `custom-fields`), `register_post_meta`
- `apiFetch`, `addQueryArgs`
- SelectControl, Spinner; block.json + render.php

## Criteria (1 point each unless noted)
1. Custom post type with `show_in_rest` and `custom-fields` support (needed for meta in the editor).
2. Role and start year registered with `register_post_meta` (`show_in_rest`, types, `single`, `auth_callback` or sanitize).
3. Routes registered with `register_rest_route` on `rest_api_init` at `team-directory/v1`.
4. List route args: role, page, per_page with types and sanitize/validate callbacks; per_page capped at 50.
5. List route has an explicit public `permission_callback` (`__return_true`), not missing.
6. Totals returned with `X-WP-Total` and `X-WP-TotalPages` headers on a `WP_REST_Response`.
7. Route provides a JSON schema.
8. Role-update route checks `current_user_can( 'edit_post', $id )` in its permission_callback.
9. Invalid input returns `WP_Error` with a status code.
10. Editor preview loads data with `apiFetch` from the custom route.
11. SelectControl role filter and Spinner while loading.
12. Front end server-rendered with escaping.
13. Member fields edited in a `PluginDocumentSettingPanel` shown only for the member post type.
14. Meta read and saved via `useEntityProp( 'postType', …, 'meta' )` (or core-data equivalent).
15. No invented or deprecated APIs (2 points: deduct 1 per instance, minimum 0).

Max: 16
