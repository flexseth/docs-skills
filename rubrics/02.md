# Rubric 02: Team Directory (REST API)

## Doc surfaces the prompt depends on
- Complex: REST API handbook (adding custom endpoints, args schema, permission_callback, `WP_REST_Response`, pagination headers)
- Non-general: `PluginDocumentSettingPanel` (`@wordpress/editor`), `useEntityProp`
- `register_post_type` with `show_in_rest` and `custom-fields` support
- `register_post_meta`
- `apiFetch` (`@wordpress/api-fetch`), `addQueryArgs`
- SelectControl, Spinner (`@wordpress/components`)
- block.json + render.php

## Criteria (1 point each unless noted)
1. CPT `team_member` registered with `show_in_rest` and `custom-fields` support.
2. `role` and `start_year` registered with `register_post_meta`, `show_in_rest`, correct types, `single`, and an `auth_callback`.
3. Routes registered on `rest_api_init` with `register_rest_route` and namespace `team-directory/v1`.
4. GET route `args` define `role`, `page`, `per_page` with type, `sanitize_callback` and/or `validate_callback`, `per_page` max 50.
5. GET route `permission_callback` is present and returns true (`__return_true`), not missing.
6. Response sets `X-WP-Total` and `X-WP-TotalPages` via `WP_REST_Response::header()`.
7. Route provides a JSON schema (`schema` callback / `get_item_schema`).
8. POST role route uses regex `(?P<id>\d+)` and checks `current_user_can( 'edit_post', $id )` in `permission_callback`.
9. POST route sanitizes the new role and updates meta, returns proper `WP_Error` with status on failure.
10. Block editor uses `apiFetch` with `path` (and `addQueryArgs`) against the custom route.
11. SelectControl filter and Spinner during loading, using hooks (`useState`/`useEffect`).
12. Block front end server-rendered in render.php with escaping.
13. `PluginDocumentSettingPanel` registered via `registerPlugin`, only on `team_member` (checks post type).
14. Meta edited with `useEntityProp( 'postType', postType, 'meta' )`.
15. No invented APIs (2 points: deduct 1 per invented function/prop, minimum 0).

Max: 16
