# Sample Documentation Contributors

Some of these roles came from `TRIAGE.md`.
Some were created specifically for this project.

These are some example user roles. 

Some roles may cross over, for example, a UX Developer may also update spelling and grammar as they review and contribute to the documentation.

Use these roles for user stories during specification.

## Contributor

This is our proof of concept: Someone who wants to update docs, or learn how the process works.
- [ ] Consolidate to `contributor.md`

A contributor is a user who wants to check out a piece of documentation to update. 

They can find the doc update needed on the WordPress Documentation Issue tracker, and use `/assign` to assign themself to the update.

Then, they will use the workflow we generate with this project to iterate through the checklist of changes needed on the doc.

Not all doc will have a checklist. Some docs contributors will want to suggest a change, maybe it's a code sample for a component that is new that does not have a code sample. In this case, they won't necessarily have a checklist, but can make the necessary changes in their sandboxed environment, and create a PR for review by other members on the documentation team.

Once pushed to GitHub, other Documentation Team members can check out the PR in Playground to see the content in the Block Editor and how it will display on the front-end of a website. The playground environment will be set up for them so that they can see how the documentation will look on the relevant WordPress property.

The dummy contributor simply uses dummy content to check things. 


## First time contributor

The entire purpose of this project is to make docs updates more approachable. 
First time contributors are the primary role we want to cater to with this project.

The `good first issues` label is made for first time contributors.

The purpose is to find relevant documentation for new contributors, guide them through the process of making updates, and help them become familiar with the contribution workflow. It shows them how to work through the changes needed, and provides guidance on contributing to the project.

Most importantly, the project should do this by making the process seamless. 

They simply find the URL of a doc they want to update, and plug it into the project. 

### Duties for first time contributors

**All purpose audit and corrections**
- Fix broken or outdated links
- Fix typos, grammar, and formatting errors in the documentation
- Ensure consistency in terminology and style throughout the documentation (learn the style guide)

**Screenshots**
- Showcase component or feature with understandable text and/or image content
- Check screenshots vs. actual implementation - is the documentation up-to-date?
- [ ] Replace broken or outdated images and media
- Make sure there is a screenshot for each option in the settings (plugin sidebar and core)
- Make sure screenshots aren't blurry
- Playwright [docs update flow](https://github.com/WordPress/Documentation-Issue-Tracker/issues/2541#issuecomment-6585941354) for screenshots

**Checklist**
- Generated by issue template for updates
- Follow the checklist provided for the documentation update

## Release Team Leads - For Docs

Updating components and interfaces as needed with new WordPress releases. Screenshots, updating how controls work, linking to relevant documentation.

## Developers

Looking at component documentations, bleeding-edge changes and changelogs, best practices and code examples. Developers look at issues related to how things work under the hood and make sure the docs are up-to-date.

### UX Developer

**Components**
Looks at all options for a components, understands how the options differs.

- create screenshots for each option for component
- notate plugin sidebar options and how they affect the underlying component
- create checklist of screenshots needed per component

**Settings**
Looks at WP Admin settings screens and how they vary from release to release.

## Writers

Content authors for the documentation use Harper.
- update spelling and grammar
- create and update screenshots for new features and components, as the interfaces change
