# Rubric 01: Recipe Scaler (Interactivity API)

## Doc surfaces the prompt depends on
- Complex: Interactivity API reference (store, context, directives), `wp_interactivity_state()`
- Non-general: `viewScriptModule` in block.json; `supports.interactivity`
- block.json metadata (apiVersion 3, render), `register_block_type`
- RichText, InspectorControls, NumberControl (`@wordpress/components`)
- `get_block_wrapper_attributes()`, `wp_interactivity_data_wp_context()`

## Criteria (1 point each unless noted)
1. block.json uses apiVersion 3, `render: file:./render.php`, `viewScriptModule`, and `supports.interactivity` (true or `{ interactive: true }`).
2. Plugin registers the block from metadata (`register_block_type( __DIR__ . '/build...' )`) on `init`.
3. Attributes defined for title, servings and ingredients with sensible types/defaults.
4. edit.js uses RichText for the title and NumberControl (or `__experimentalNumberControl`) in InspectorControls for servings; ingredients are editable.
5. view.js imports `store` (and `getContext`) from `@wordpress/interactivity` and defines a namespaced store with actions and derived state/getters.
6. render.php sets `data-wp-interactive` with the store namespace on the wrapper.
7. Per-block context is output with `wp_interactivity_data_wp_context()` (or correctly escaped JSON in `data-wp-context`).
8. `data-wp-on--click` wired to increment and decrement actions.
9. `data-wp-text` used for scaled quantities and the servings count.
10. `data-wp-bind--disabled` (or equivalent) disables "−" at 1 serving.
11. `wp_interactivity_state()` (or server-computed values) makes initial markup correct before JS runs.
12. Quantities rounded to two decimals in the scaling logic.
13. Output escaped in render.php (`esc_html`, `esc_attr`, `get_block_wrapper_attributes`).
14. No invented APIs (2 points: deduct 1 per invented function/directive/prop, minimum 0).
15. package.json with `@wordpress/scripts` and a build script that handles script modules (`--experimental-modules` or equivalent).

Max: 16
