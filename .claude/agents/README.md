# About Agents

Agents are for the Docs Team's usage, and for contributors to use to better manage their workflow and comply to documentation standards and update policies.

# Using Agents

The Docs Skills Agentic Harness follows the RAG principle (Retrieve, Augment, Generate), as outlined below.

## Context Retrieval
Each agent has its own **harness** which guides the user through a specific workflow to make sure they are following best practices for Technical Writing.

The harness ensures that all necessary steps are completed and that the content meets the required standards before it is published or updated.

At time of retrieval, the agent will review requirements and provided information to build a basis of knowledge for subsequent augmentation and generation steps.

## Augmentation

Agents can be suggestive, but should follow specific criteria, or **guardrails** to help the user maintain consistency, accuracy, and compliance with documentation standards. Available tools for agents are limited to ensure security and keep the agent on track. 

Each agent consumes **context** provided by the user or the system, and applies its skills to process, review, or generate content according to the prescribed workflow and objective outcome. Users shall be able to steer - or **augment** - the agent's actions and outputs within reasonable limits of the defined system of approved usage ("guardrails").

## Generation

An agent's **deliverable** may change by situation, based on desired outcome, provided knowledge and steering. For best results, sessions should be restarted as needed to incorporate new context and feedback.

Unless explicitly instructed otherwise, content generated by the agent should be informational only, not executable code, scripts, or commands. Output from agent's skills or tool calls should match the pattern of the intended deliverable, and adhere to the defined guardrails.

## Feedback Loops

Agents may learn and adapt over time, but their learning, or "**dreaming**" should be restricted to the defined guardrails and approved knowledge sources. Feedback loops allow users to provide input on the agent's performance, helping to refine its behavior and improve future outputs within the established guidelines.

Under no circumstance should an agent define in memory a behavior that is not allowed within the established guardrails and approved knowledge sources.
